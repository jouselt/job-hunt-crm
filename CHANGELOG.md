# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Continuous integration: backend build, lint and tests, frontend tests and build,
  and a job that regenerates the scoring rules and the golden fixture from the
  Python source of truth and fails if they drift.
- Multi-arch (`amd64` and `arm64`) images published to GHCR on tags, so a homelab
  on ARM pulls instead of compiling.
- `tools/`: the Python ranker that is the source of truth for the vacancy scoring,
  the generators for the TypeScript rules and the golden fixture, and their tests.
  They were previously outside the repository, which left the generated file
  pointing at a script nobody else had.
- `tools/fixtures/triage-profile.example.json` and `tools/fixtures/corpus.json`, so
  the scoring artifacts can be regenerated by anyone from what is in the repository.
- `.dockerignore` for both services. The build context no longer ships ~600 MB of
  `node_modules` to the daemon, and the local `.env` stays out of the intermediate
  build layer.
- ESLint configuration for the backend. The `lint` script existed and could not run.
- `CHANGELOG.md`, `CONTRIBUTING.md`, and issue and pull request templates.

### Changed

- The default triage profile is now a generic example. It previously held the
  author's own profile, including employers, education and work-permit status, and
  it is what every new install scored against until the user configured their own.
- `npm test` in the frontend runs headless without watch, which is the only form
  that can finish in CI. `npm run test:watch` keeps the watch behaviour.
- README: documents the vacancy scoreboard, the `saved` stage and the full API
  surface. It previously described eight of the twenty-four endpoints.

### Fixed

- Freshness is measured in days against a 30-day window instead of calendar-month
  arithmetic, which counted month boundaries and awarded the bonus to postings from
  July. In production the signal fired on 94 of 100 admitted postings; it now fires
  on 47, with zero rows disagreeing with the window.
- The application detail view no longer reports a CRM offer as unsaved. An offer
  from the CRM is in the pipeline by definition; `tracked` is a feed concept.
- Removed dead code that the new linter surfaced: an unused CHECK-constraint
  builder in the application entity, an unused import, and an unused date in the
  seed.

## [0.1.0] - 2026-09-21

### Added

- Applications CRUD with source, stage and notes.
- Stage pipeline `saved → applied → screened → interview → offer`, with `rejected`
  terminal. `saved` is the entry point: tracking a posting records that you saved
  it, not that you applied. `applied_date` is sealed when a row reaches `applied`.
- Follow-up scheduling, a due view, and a daily reminder.
- Pipeline analytics per stage.
- Offer triage against the TypeSafe Jev API with deterministic thresholds.
- Vacancy scoreboard over a job feed, scored against the user's own profile, with
  the score breakdown behind every row, `Track` into the pipeline and `Gone` for
  postings that have closed.
- Per-user isolation on every query, backed by PostgreSQL row-level security.
- JWT authentication with bcrypt password hashing.
- Docker Compose stack with healthchecks, a Caddy subpath example, and a NixOS
  module example.
